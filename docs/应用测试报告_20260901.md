**计算内核本身是扎实的**:18 组政策口径在"单一情形"下逐条验证,55 项断言全部正确(10% 限额公式、委托 80%、境外 2/3、境外个人不得加计、受托开发整项目剔除、资本化 200% 摊销、特殊收入冲减顺序、不征税收入剔除、IC 120% 及适用期、亏损结转年限、四档税率模型、三套口径、预缴截断、负面清单)。前端 12 个页面零 JS 错误,8 个导出接口全部可用,数电票解析与 GBK/UTF-8 编码识别均正确。

**但组合场景下存在 1 个 P0 级政策口径错误**:当账套里同时存在「费用化项目」与「尚未结题的资本化项目」时,系统把资本化项目的本年支出提前计入了其他相关费用限额基数与 A107012 第 2~39 行,与国家税务总局公告 2021 年第 28 号第三条规定不符 —— 详见 P0-1。这是本次测试最重要的发现,也是文档预期值(109,555.56)与系统实际值(175,666.67)对不上的**真实原因:文档是对的,代码是错的**。

## 二、缺陷清单

### P0-1 【政策口径错误】尚未形成无形资产的资本化支出被计入限额基数与 A107012 第 2~39 行

**现象**
申报汇总页「其他相关费用限额」= 175,666.67,A107012 行 40 小计 = 1,869,000、行 42 本年资本化金额 = 595,000;而按政策应为 109,555.56 / 1,274,000 / 0。

**政策依据**
1. 《国家税务总局关于进一步落实研发费用加计扣除政策有关问题的公告》(2021 年第 28 号)第三条:
   > 全部研发项目的其他相关费用限额 = 全部研发项目的人员人工等五项费用之和 × 10%/(1-10%),**其中资本化项目发生的费用在形成无形资产的年度统一纳入计算**。
2. A107012 填报说明(2024 版)首段:
   > 对于资本化的研发支出,在无形资产形成年度,第 2 行至第 39 行应包含当年度及以前年度为该项无形资产的所有研发支出;**尚未形成无形资产的年度和形成无形资产之后的年度,第 2 行至第 39 行不包含该项无形资产的研发支出**。
3. 行 42 填报说明:「填报纳税人研发活动**本年结转无形资产的金额**」(不是本年发生的资本化支出)。

来源:
- https://www.shui5.cn/article/92/117537.html (A107012 2024版表式及填报说明全文)
- http://www.dqcpa.cn/a/202505/1q2n8qb534vlp.shtml (12366 会填表,引 28 号公告原文)
- https://guangdong.chinatax.gov.cn/gdsw/zssw_nsrwkt_sphg_zbsp/2024-05/08/1441270a92074091b4c93eaebcb45a2d/files/b2e7d82a53714592ba20fb6bb36acd2c.pdf (广东省税务局纳税人学堂)

**代码位置**
- `src/summary.js:75` `otherLimit = (base5 + base5Cap) * 0.1 / 0.9` —— 无条件含资本化
- `src/summary.js:83` `domesticTotal`(境外 2/3 限额基数)同样含资本化
- `src/summary.js:271-283` `buildA107012` 的 `fiveTotal / line2 / line40 / line42`
- 注释 `src/summary.js:69` 明写「含资本化支出」,为有意设计但口径引用有误

**量化影响**(构造场景:费用化项目前 5 类 98.6 万 + 其他费用 15 万 + 委托境内 30 万;资本化项目本年支出 59.5 万未结题)

| 项目 | 系统当前 | 正确口径 | 差异 |
| --- | ---: | ---: | ---: |
| 其他相关费用限额 | 175,666.67 | 109,555.56 | +66,111.11 |
| 其他费用可扣除 | 150,000.00 | 109,555.56 | **+40,444.44** |
| 超限剔除 | 0.00 | 40,444.44 | -40,444.44 |
| 委托境外 2/3 限额基数 | 1,971,000.00 | 1,335,555.56 | +635,444.44 |
| A107012 行 42 资本化 | 595,000.00 | 0.00 | +595,000.00 |

→ 多计加计扣除额 40,444.44 元,按小微 5% 税负多抵税款 2,022.22 元,按 25% 税率 10,111.11 元。
→ 演练场景(其他费用 4.8 万未超任一限额)下加计基数 1,274,000 恰好不受影响,**但只要其他费用 > 109,555.56 或存在委托境外支出,即产生实质差异**。

**修复建议**
需为项目增加「形成无形资产年度」字段(如 `intangibleYear`),限额计算与 A107012 第 2~39 行仅在该年度纳入该项目的全部资本化支出(当年度及以前年度累计);未设置该字段的资本化项目,按"尚未形成无形资产"处理,不纳入。
> MANUAL_REVIEW:修复需新增字段并涉及年度汇缴口径切换,建议确认后再改。

### P0-2 【业务漏洞】共用费用分摊到费用化项目的资本化支出,永久无法摊销加计

**现象**
共用折旧按工时分摊时,分摊额**继承源费用的 `capitalization` 属性**。P2(资本化项目)的 35,000 元折旧按 2026-06 工时(464:104)分摊后,P1 分得 28,591.55 元且仍标记为「资本化」。但 P1 的支出政策是费用化,而摊销计划接口 `/api/amortization/plan` 只允许 `capitalization === 'capitalize'` 的项目生成摊销 —— 这 28,591.55 元既不在费用化加计基数里,也无法生成摊销计划。

**实测**
```
申报汇总页「资本化形成无形资产成本」 = 595,000.00
各项目可生成摊销计划金额合计         = 566,408.45   (P2 一个项目)
差额                                =  28,591.55   ← 挂在 P1(费用化)名下,无出路
```
辅助账显示 P1:合计 1,353,802.82(费用化 1,325,211.27 + 资本化 28,591.55)。

**影响**:只要企业存在「共用折旧/摊销 + 项目支出政策不一致」(中小企业极常见),这部分支出就永久损失加计。按 200% 摊销 10 年、5% 税负估算,单此一项约 1.4 万元节税损失,且申报页数字与摊销计划对不上会让用户困惑。

**修复建议**(三选一,需业务决策)
- A:分摊时按**目标项目**的 `capitalization` 重新归类(费用化项目收到的分摊额一律转费用化)—— 最符合直觉,但会改变辅助账现有数字
- B:允许费用化项目对"收到的资本化分摊额"单独生成摊销计划
- C:不动计算,在申报页/摊销页增加差异提示与手工结转入口
> MANUAL_REVIEW:涉及会计处理口径选择,建议由业务侧定夺。

### P0-3 【对账不一致】孤儿费用在两套口径中被区别对待

**现象**
费用关联的 `projectId` 不存在时(项目被删除、或录入时填了不存在的 ID),`computeSummary` 会把它计入加计基数,而 `buildA107012` 在 `src/summary.js:252` 有 `if (!proj) return;` 直接跳过 —— 两套口径对不上,辅助账还多出一个幽灵项目区块。

**实测**
```
computeSummary 加计基数 = 1,277,000.00
A107012 行41 费用化金额 = 1,276,000.00
差额                   =     1,000.00  ← 一笔 projectId='not_exist' 的费用
辅助账项目列表:2026-RD-01 / 2026-RD-02 / (无编号) not_exist  1,000.00
```

**触发路径**
1. 会计录完费用后把项目删了(无级联删除、无提示)
2. `POST /api/expenses` 不校验 `projectId` 是否存在(实测返回 201)

**修复建议**:录入时校验 projectId 存在性;计算层统一以「项目存在」为前提过滤;删除项目时提示关联费用数量并要求确认。
